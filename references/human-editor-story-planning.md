# 人工编辑故事规划方法

## 1. 使用边界

把人工大纲、章纲、正文批注视为方法证据，而不是剧情模板。先提炼编辑为什么这样安排，再判断是否可跨题材迁移。禁止复制样稿的人物、专有名词、谜题、情节组合、台词或独特反转。涉及样本学习时先读取 `reference-sample-transfer-policy.md`，标记 Audience、产品、Genre、篇幅、叙事模式和证据强度。

单一样本反复出现的方法先记为候选策略；多个优质人工样本独立重复出现，且不依赖特定题材时，才升级为通用强规则。用户明确要求某项目复刻结构时，也只能复刻抽象结构，不照搬内容。

## 2. 章纲必须是客观事件施工图

章纲的核心不是“这一章想表达什么”，而是“这一章实际发生什么”。每个核心事件写成：角色或力量主体 → 可观察行动 → 直接结果 → 状态变化。

不合格示例：营造紧张感、突出主角聪明、加深关系、增强危机。

合格转换：敌人封死出口 → 主角发现旧门锁有使用痕迹 → 主角用低风险方法试锁 → 暗门开启但触发倒计时 → 队伍被迫改变路线。

判断标准：只把章纲交给另一个作者，他是否能据此写出明确场景和因果链。若不能，继续具体化。

## 3. 每章设置推进变量

相邻章节不能只换危险场景重复同一结构。每章至少推动一个变量发生实质变化：
- 规则认知；
- 当前任务目标；
- 队伍结构；
- 资源或道具；
- 敌人能力或限制；
- 地图或环境条件；
- 失败代价；
- 人物关系；
- 世界信息。

连续两章若所有变量都未变化，优先合并、压缩或改写后一章。

结构推进之外，还要检查读者欲望推进：当前最强问题是什么，本章给出什么答案或回报，答案之后形成什么更具体的问题、目标或情绪期待。事件数量增加但读者问题和期待不变，不算有效留存推进。

## 4. 主角能力要尽早兑现

不要只在人设表声明主角聪明、勇敢、特殊。尤其是开篇和短集有声故事，要检查：首次台词、首次主动决策、首次核心能力展示、首次让他人改变判断的外部反馈。

具体出现位置由本项目单集长度和产品形态决定，不设置跨项目统一字数线。但不要让大量环境、系统说明、路人恐惧或配角行动挤掉主角的首次主动行为。

## 5. 聪明主角用证据链证明

优先使用：观察事实 → 提出假设 → 找对照或反例 → 低成本验证 → 得到结论 → 实战兑现。

如果证据只支持“可能”，主角只能提出假设，不能直接获得正确答案。若结论会决定生死，应尽可能加入测试、对照、先例或能力辅助验证。

推理爽点来自听众能回看证据并理解主角为什么对，而不是旁白宣布“他瞬间明白一切”。

## 6. 高风险选择先建立必要性

重大冒险、开箱、越级挑战、闯禁区、公开身份等行为之前，先回答：更安全的选项为什么不可行、代价更大、已经失效或时间来不及。

推荐因果链：安全方案被封死 → 剩余方案比较 → 高风险方案成为受约束下的最优解 → 执行 → 承担后果。

不要用“主角胆子大”替代必要性。

## 7. 优先行动型章末钩子

章末优先留下一个下一章必须马上处理的问题：逼近危险、倒计时、两难选择、目标突变、队友即将犯错、资源即将失效、身份即将暴露。

弱钩子只是“还有一个秘密”。强钩子让听众立刻问“现在怎么办”。信息型秘密可以存在，但最好绑定行动压力。

## 8. 团队按能力拼图设计

核心队员至少明确：能力、信息来源、短板、不可替代任务。

做“删除角色测试”：若删除某核心成员，关键剧情仍可几乎原样完成，说明其功能不足。优先重新分配信息、决策、执行、保护、情感或资源职责。

团队合作章要写清：谁发现、谁判断、谁执行、谁承担风险或完成不可替代动作，避免所有关键问题都由主角一人包办，配角长期只负责惊叹。

## 9. 有声书必须听觉可辨

现实人物、系统播报、直播/弹幕、远端通讯、内心独白、回忆、梦境等来源切换时，不能依赖颜色、排版、用户名位置或画面框。通过旁白过桥、声效、固定播报句式、稳定标签或声音特征建立来源。

首次切换要更清楚，听众建立规则后才可适度简化。关键情报不能只存在于视觉格式。

## 10. 小剧情单元采用认知升级链

规则、悬疑、智斗、副本类故事可优先设计：未知 → 观察 → 假设 → 验证 → 利用 → 升级或反转 → 新问题。

危险升级不等于敌人数字变大。更有效的升级是旧答案只解决部分问题，随后规则、任务、资源、队伍或代价改变，迫使角色重新思考。

## 11. 审计顺序

先修因果和行动逻辑，再修句子。若“为什么必须这样做”不成立，文笔再华丽也不通过。

审计优先级：客观事件链 → 因果必要性 → 推进变量 → 读者问题与承诺兑现 → 主角能力兑现 → 信息/推理证据 → 团队功能 → 章末钩子 → 有声来源辨识 → 文风。
