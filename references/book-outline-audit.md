# 全书大纲审计

## 必查

- 核心命题、终局、主角目标与分阶段目标是否一致。
- 主线、主要支线、关系线是否有开始、推进和回收。
- 每卷/大型单元是否有清晰的功能与推进变量。
- 相邻大型单元是否至少改变规则认知、目标、队伍、资源、敌人、环境、代价、关系或世界信息之一，而非只换地图重复同一危机。
- 信息释放是否形成认知升级，智斗/规则题材避免主角无证据开挂式猜中。
- 核心队伍是否形成能力拼图：能力、信息来源、短板、不可替代任务明确。
- 重大冒险和反转是否有足够前置因果。
- 高潮、回报、缓冲与失败代价是否随长线升级。
- 书名、简介、标签和核心设定形成的作品承诺是否进入规划；第一次小兑现、阶段升级、中期再立题、阶段大兑现和终局兑现是否明确。
- 每次兑现后是否产生新目标、新问题或更高代价，避免长篇只拖延一个承诺或一次还清后失去动力。
- 长期读者问题链是否通过“问题 → 部分答案 → 更具体/更严重问题”持续推进，而非只开新谜团不回答。
- 关系驱动项目是否规划主要情绪债的建立、加深、局部偿还和最终偿还，以及关系状态的阶段变化。
- 高潮后是否安排余波，用可观察的生活、关系、规则或行动证明不可逆变化已经生效。
- 体量是否与剧情单元承载力匹配，避免为凑章数重复任务。
- Project Profile 的年龄、听觉理解、产品单位和题材强度是否匹配。

成人网文型项目同时加载 `adult-webfiction-engagement.md`；情感或同人专项只在 Profile 匹配时启用。任何样本规则先通过 `reference-sample-transfer-policy.md` 的适用范围检查。

## 审计结果

按 Critical / Major / Minor / Note 输出。Critical 与未接受的 Major 修复前不得提交用户批准。
