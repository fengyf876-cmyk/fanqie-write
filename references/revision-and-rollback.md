# 章纲修改与回滚

## 未来未写

用户明确要求修改未来章纲时可直接实施，升级版本并局部重审，不回滚已批准历史。若触及宏观节点，同步 Book Outline。

## 当前未批准批次

修改章纲后，从 batch base checkpoint 重建临时状态，从最早受影响章重写或复核；章纲和正文 DOCX都重新导出。

## 已批准历史

若会改变既成事实，创建 Change ID，标明最早/最晚受影响章节，判断后文 current / revalidate / stale / superseded，给出最小重写方案和回滚点，等待用户确认后执行。优先寻找状态重新收敛点，不默认重写全部后文。
