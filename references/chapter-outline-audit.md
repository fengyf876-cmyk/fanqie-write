# 章纲审计

## 审计目标

判断章纲是否足以指导正文生产，并保证每章推动故事而不是重复气氛或危险。审计时同时读取已批准大纲、体量计划、Project Profile 和 `human-editor-story-planning.md`。

## Critical

- 违反已批准世界规则、人物命运、重大节点或用户硬约束。
- 关键因果断裂，角色无理由获得信息、道具、能力或突然改变目标。
- 关键推理直接跳到答案，没有足够证据且该答案决定重大结果。
- 高风险行为明显有安全且等价的方案，却没有解释为何不用。

## Major

- 章纲核心仍是“营造气氛、突出聪明、加深感情”等创作意图，而不是客观事件。
- 连续两章没有任何推进变量变化，只重复相同危机结构。
- 开篇或短集连续消耗大量篇幅给环境、系统、路人，主角迟迟没有主动行为和核心能力兑现。
- 核心队员长期没有不可替代任务，删除后剧情几乎不受影响。
- 章末只有模糊秘密，没有明确行动压力，且连续多章如此。
- 多声源有声场景依赖视觉排版才能判断是谁在说话或信息来自哪里。
- 当前问题、读者问题与人物行动脱节，章节发生很多事却没有形成明确的下一步期待。
- 承诺长期只有延迟和提醒，没有真实答案、回报或状态变化。
- 关系驱动章节只写“争吵/和解/加深感情”，没有双方判断、行动依据和关系出口状态。
- 重大外部事件结束后，主线状态与人物关系均无变化。

## Minor

- 单章事件过多，目标单位字数承载不下。
- 爽点、笑点、知识点或悬念与 Profile 不匹配。
- Hook 开启、推进、回收时点模糊。
- 角色贡献失衡但尚未影响主线。

## 每章检查字段

至少确认：当前核心问题、人物为什么现在必须行动、客观核心事件链、推进变量、冲突、信息释放、主角主动行为/能力兑现、当前读者问题、本章答案/兑现、兑现后的新问题或新欲望、人物关系入口与出口状态、回报、伏笔、状态变化、收尾客观事件、行动型钩子、有声化设计。

关系驱动项目额外确认情绪债处于建立、提醒、加息、局部偿还还是最终偿还；外部事件具体改变了信任、依赖、距离、控制权、认知、承诺、公开程度或关系身份中的哪一项。

智斗章额外确认“证据 → 假设 → 验证 → 结论 → 实战”。团队章确认“发现者 / 判断者 / 执行者 / 不可替代贡献”。冒险章确认“安全方案为何不可行”。

成人网文型项目加载 `adult-webfiction-engagement.md` 及其匹配的专项模块。不得把成人情感检查套用到少儿或不匹配题材。

## 通过标准

Critical 必须为0；Major 必须为0或已由用户明确接受；Minor 可带说明进入用户审核。内部通过不等于用户批准。
